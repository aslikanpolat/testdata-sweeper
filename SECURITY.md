# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected security vulnerability. Report it privately through the repository security contact or GitHub Security Advisories for [aslikanpolat/testdata-sweeper](https://github.com/aslikanpolat/testdata-sweeper/security).

Include the affected version, reproduction steps, impact, and any suggested mitigation. Do not include production credentials or sensitive customer data.

## Scope

The most important security boundaries are database target allowlists, production rejection, prefix validation, identifier validation, and recovery manifest ownership checks. Changes that weaken these boundaries require explicit tests and documentation.
